# VibeBoss M1：基于 T3 Code 的魔改范围

VibeBoss 是在 T3 Code（pingdotgg/t3code，MIT）上做的分支，给不写代码的人用：Claude、Codex、Agy 三家智能体在一个桌面应用里协作。原则是**能用 T3 已有的就用，只在缺的地方加**；每次改动都在这里登记“改了哪、为什么、上游更新时要注意什么”，方便以后跟进 T3 的新版本。

分支：`vibeboss/m1-slim`（基于 T3 `main`）。只在本地，未推送。

## 跟进上游时的总原则

- 其他 8 家智能体是**藏起来，不是删掉**：上游改它们的代码照常合并，不会冲突。
- 新功能尽量放在新文件里（`vibeboss/` 目录、`VibeBoss*.tsx`），只在上游文件里加入口。
- 合并上游后先跑：`vp run typecheck`、`vp test run apps/server/src/vibeboss`，再看本文件里每一节的“上游注意”。

## 3. 分工、规则、技能·MCP·插件三个页面

- **需求**：统一管理各家的全局声明；设一个主控和若干有名字的成员；主控规则只给主控读；看三家装了哪些技能、MCP、插件。
- **复用 T3**：派活用 T3 自带的 `delegate_task`（`target.providerInstanceId / model / options`）；智能体列表用 T3 的已启用提供方；页面框架用 T3 的 `WorkspacePageHeader`、`SidebarInset`。
- **数据**：配置存在 `<T3 数据目录>/vibeboss/config.json`；开发版同步只写 `vibeboss/preview/`，不碰真实文件；正式版写入前先备份到 `vibeboss/backups/`。旧版配置首次读取时自动迁移。
- **规则文件生成**：
  - 每个已启用的智能体各一份全局声明：Claude `~/.claude/CLAUDE.md`、Codex `~/.codex/AGENTS.md`、Agy `~/.gemini/GEMINI.md`、Hermes（ACP 注册表）`~/.hermes/SOUL.md`。
  - 主控那一家的文件后面加“主控规则”和成员清单；`@成员名` 自动展开成当前背后的智能体和派活命令，换智能体不用改规则。
  - 每家都加“被派活时只做这件事，不再往下派”。
- **分工页的模型和档位**：下拉选项直接取 T3 的提供方模型列表（`ServerProvider.models`）和该模型自带的档位选项（`isReasoningSelect`，和对话里的档位选择器同一来源）；存模型编号（旧配置里的显示名用 T3 的 `resolveSelectableModel` 自动认出）。生成规则时把模型编号和档位直接写进 `delegate_task` 的 `target.model` / `target.options`，主控不用再自己查档位参数。换智能体时模型和档位清空重选。备注平时显示成文字，点铅笔才变输入框（`MemberFields.tsx`）。
- **改动**
  - 合约：`packages/contracts/src/vibeboss.ts`、`packages/contracts/src/rpc.ts`（5 个 `vibeboss.*` 方法）
  - 服务端：`apps/server/src/vibeboss/VibeBoss.ts`（及测试）、`apps/server/src/ws.ts`、`apps/server/src/auth/RpcAuthorization.ts`、`apps/server/src/observability/RpcInstrumentation.ts`
  - 前端状态：`packages/client-runtime/src/state/vibeboss.ts`、`apps/web/src/state/vibeboss.ts`
  - 页面：`apps/web/src/components/vibeboss/*`，路由 `_chat.agents.tsx`（分工）、`_chat.rules.tsx`、`_chat.capabilities.tsx`
- **上游注意**：`rpc.ts`、`RpcAuthorization.ts`、`RpcInstrumentation.ts` 是全量登记表，上游加方法时会有相邻冲突，按两边都保留处理。上游如果改了 `delegate_task` 的参数，要同步改 `VibeBoss.ts` 里的 `delegateCall`。

- **已收尾**：做完的会话挪到底部“已收尾”，不删、能搜，再发消息自动回到主列表；默认 7 天没动静或 PR 合并后自动收尾。左上角“项目”筛选选中某个项目时，“已收尾”也只显示这个项目的。

## 不接 T3 云（本地版）

- **决定**：VibeBoss 先做纯本地版，不用 T3 Connect 账号登录和云同步；以后要同步，用自己的服务器。
- **复用 T3**：T3 的账号登录、T3 Connect、云中转全部由 `hasCloudPublicConfig()` 控制，只有构建时填了 `T3CODE_CLERK_PUBLISHABLE_KEY`、`T3CODE_CLERK_JWT_TEMPLATE`、`T3CODE_RELAY_URL`（或对应 `VITE_*`）才会出现。VibeBoss 构建**不填这几项**，登录入口、账号头像、T3 Connect 设置和引导弹窗都不会出现，不用改代码。
- **不是云登录的**：开发版在浏览器里打开时偶尔出现的“配对”页，是本机服务的访问口令（`/pair`），只在浏览器版出现，桌面版自动配好。
- **匿名使用统计也关掉**：T3 默认把匿名使用数据发到 T3 自己的服务器（`ingest.t3.codes`，密钥写死在代码里）。VibeBoss 改成默认关（`apps/server/src/telemetry/AnalyticsService.ts` 的 `T3CODE_TELEMETRY_ENABLED` 默认 false），欢迎页和设置里“我们会收集匿名数据”的说明一并隐藏（开关 `VIBEBOSS_T3_TELEMETRY`，在 `apps/web/src/vibeboss.ts`）。
- **上游注意**：上游新加云功能时，看它是否也挂在 `hasCloudPublicConfig()` 下；没挂的要单独藏。上游改遥测默认值时保留关闭。
