# VibeBoss M1：基于 T3 Code 的魔改范围

VibeBoss 是在 T3 Code（pingdotgg/t3code，MIT）上做的分支，给不写代码的人用：Claude、Codex、Agy 三家智能体在一个桌面应用里协作。对外只叫 VibeBoss，内核持续跟进 T3。原则是**能用 T3 已有的就用，只在缺的地方加**；每次改动都在这里登记“改了哪、为什么、上游更新时要注意什么”。

仓库：私有 `AKin-lvyifang/vibeboss`，`main` 为最新。

## 跟进上游时的总原则

- 仓库**不会自动同步** T3，要手动合并：`git fetch upstream && git merge upstream/main`。我们的改动会保留，冲突的地方逐个处理。
- 尽量勤合（一两周一次）：T3 一天能有两百多个提交，拖久了冲突会越积越多。
- 其他 8 家智能体是**藏起来，不是删掉**：上游改它们的代码照常合并，不会冲突。
- 新功能尽量放在新文件里（`vibeboss/` 目录、`VibeBoss*.tsx`），只在上游文件里加入口。
- 合并后：文案冲突先取上游版本，跑 `vp run vibeboss:rebrand`；再跑 `vp run typecheck`、`vp test run apps/server/src/vibeboss`，看本文件每一节的“上游注意”；最后重新打包。
- `LICENSE` 里 T3 的版权声明要保留（MIT 要求），界面里不显示即可。
- **登录原则**：不管哪个版本、给谁用，都和 T3 原生一样，由用户自己登录各家智能体、用自己的额度；VibeBoss 不内置任何人的账号、令牌或公司网关。

## 10. Agy 用量额度显示

- **问题**：Agy 已用 Google 账号登录、能聊天，但“用量 → 限制”提示“Sign in with Google”。
- **原因**：T3 让 Agy 把登录令牌存成文件（假装 SSH 会话），额度读取只认那个文件；agy 1.5.15 起仍把令牌存进系统钥匙串（服务 `gemini`、账号 `antigravity`），而 T3 只在企业账号时才读钥匙串。
- **改动**：`apps/server/src/provider/antigravityUsageLimits.ts` 个人 Google 账号找不到令牌文件时也读钥匙串（及对应测试）。代价：如果这台电脑上别的应用（比如 Antigravity IDE）用另一个 Google 账号登录过，可能显示那个账号的额度。
- **上游注意**：上游修了这个问题后，以上游为准撤掉这处改动。

## 不接 T3 云（本地版）

- **决定**：VibeBoss 先做纯本地版，不用 T3 Connect 账号登录和云同步；以后要同步，用自己的服务器。
- **复用 T3**：T3 的账号登录、T3 Connect、云中转全部由 `hasCloudPublicConfig()` 控制，只有构建时填了 `T3CODE_CLERK_PUBLISHABLE_KEY`、`T3CODE_CLERK_JWT_TEMPLATE`、`T3CODE_RELAY_URL`（或对应 `VITE_*`）才会出现。VibeBoss 构建**不填这几项**，登录入口、账号头像、T3 Connect 设置和引导弹窗都不会出现，不用改代码。
- **不是云登录的**：开发版在浏览器里打开时偶尔出现的“配对”页，是本机服务的访问口令（`/pair`），只在浏览器版出现，桌面版自动配好。
- **匿名使用统计也关掉**：T3 默认把匿名使用数据发到 T3 自己的服务器（`ingest.t3.codes`，密钥写死在代码里）。VibeBoss 改成默认关（`apps/server/src/telemetry/AnalyticsService.ts` 的 `T3CODE_TELEMETRY_ENABLED` 默认 false），欢迎页和设置里“我们会收集匿名数据”的说明一并隐藏（开关 `VIBEBOSS_T3_TELEMETRY`，在 `apps/web/src/vibeboss.ts`）。
- **上游注意**：上游新加云功能时，看它是否也挂在 `hasCloudPublicConfig()` 下；没挂的要单独藏。上游改遥测默认值时保留关闭。

## 12. Agy 钥匙串只读一次

- **问题**：上面第 10 条让额度读取去钥匙串拿令牌，每次刷新额度都读一次，macOS 反复弹“node/VibeBoss 想要使用钥匙串里的 gemini”。
- **改动**：`antigravityUsageLimits.ts` 把读到的令牌留在内存里，过期前不再读钥匙串（及对应测试）。弹窗里点“始终允许”，之后就不会再问；重新安装新打的包后可能再问一次（ad-hoc 签名每次不同）。

## 13. Windows 安装包

- **做法**：Mac 上打不了 Windows 包，用 GitHub 云端 Windows 机器打：`.github/workflows/vibeboss-windows.yml`，手动触发（`gh workflow run vibeboss-windows.yml`），产出未签名的 `.exe` 安装包，在运行记录的附件里下载。Windows 第一次运行会提示“已保护你的电脑”，点“更多信息 → 仍要运行”。
- **与上游的差别**：上游在 Linux 上交叉编译 Windows 包，会自动跳过“服务端编译缓存”；我们在 Windows 机器上原生打，缓存多出 37 个文件，超过安装包 80 个文件的上限，所以用 `VIBEBOSS_SKIP_SERVER_COMPILE_CACHE=true` 跳过（`scripts/prepare-server-compile-cache.cjs`）。
- **测试**：改名后本机跑了受影响的 153 个测试文件；分诊提示词（`apps/server/src/triage/`）必须和上游 `.github/triage/PLAYBOOK.md` 一字不差，改名脚本跳过它。其余失败的（用量统计、Git、部分编排测试超时、Linux 专属、ssh）与改名无关，改名前同样失败，多是本机 Node 版本较旧所致。
- **仓库**：私有仓库 `AKin-lvyifang/vibeboss`。上游 T3 自带的自动化流程（CI、发布、移动端等）在这个仓库里停用，它们依赖 T3 自己付费的构建机器，跑不起来。

## 14. Agy 用量登录过期后自动续期

- **需求**：用量页里 Agy 经常显示“saved sign-in has expired”，看不到额度。
- **原因**：agy 把 Google 登录存在钥匙串里，一小时就过期；里面没有可供 VibeBoss 自己续期的信息，T3 的做法是提示“去跑一次 Agy 对话”。
- **做法**：发现过期时，后台跑一次 `agy models`（只列模型、不耗额度），agy 会顺手把钥匙串里的登录续上，再重读一次。最多 10 分钟试一次，不会反复跑。改在 `antigravityUsageLimits.ts`（`renewSignIn`）和 `AntigravityDriver.ts`。
- **上游注意**：上游如果能自己续期 agy 登录，以上游为准撤掉这处。
