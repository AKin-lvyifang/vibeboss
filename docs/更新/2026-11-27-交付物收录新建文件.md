# 交付物面板收录 Claude 和 Antigravity 新建的文件

- 需求：右侧「交付物」面板漏掉 Claude、Antigravity 新建的文件，只有回复里写了链接或路径的才显示。
- 原因：面板（`deliverablesOf`）靠「文件变更」记录里的 `changes` 清单认新建文件（操作为 add / create / write）。只有 Codex 填这份清单；Claude 和 Antigravity 不填，这条路对它们一直是空的。网页端拿不到 diff 原文（传输时去掉了），只能在服务端适配器补。
- 做法：
  - Claude：Write 的返回结果自带 `type: "create" | "update"`。`ClaudeAdapterV2.ts` 据此填 `changes`：新建记 `add`，Edit 和覆盖已有文件记 `update`（不进面板）。
  - Antigravity：它不区分新建和覆盖（原始记录里 Overwrite 一律为 true），只能按工具区分。`AntigravityProtocol.ts` 把整文件写入（`write_to_file`，参数带 `CodeContent`）记为 `write`，局部替换（`replace_file_content`）不记。重写已有文件也会进面板，同一文件只占一行。
  - `packages/provider-acp/src/server/adapter.ts`：带 `changes` 的变更遵守「不可预览就不放 diff」，和原来没 `changes` 时一致。
- 复用 T3：`file_change.changes` 字段和 Codex 同一套，面板代码不用改。
- 测试：`ClaudeAdapterV2.test.ts` 加新建 / 修改 / 覆盖三种的 `changes` 断言；`AntigravityProtocol.test.ts` 加整文件写入和局部替换。`AcpAdapterV2.test.ts` 的「fidelity updates」用例改动前就失败（网页搜索结果断言），与本次无关。
- 不做：用命令行脚本生成的文件没有「文件变更」记录，仍要 Agent 在回复里写出路径才会收录。
- 待验证：Antigravity 的参数名取自上游测试，未用真实 Antigravity 会话跑过。
- 上游注意：合并上游时这三处若被改，保留 Claude 的 `claudeFileChanges` 和 Antigravity 的 `antigravityWrittenFile`。
