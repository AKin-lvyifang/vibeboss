# 自动更新（检查更新 + 一键更新）

- **需求**：装了 VibeBoss 的人，在我们发新版（GitHub Release）后能自动发现；点一下就后台下载，下载完自动安装并重启。
- **复用 T3**：T3 自带完整的桌面自动更新（`electron-updater`：定时检查、下载进度、重启安装、侧边栏更新按钮、设置页「版本」一栏）。更新源由打包时写进安装包的 `app-update.yml` 决定。VibeBoss 只改了更新源和按钮流程，没有另起一套。

## 改了什么

- **更新源指向我们的仓库**：新文件 `packages/shared/src/vibebossRelease.ts`（`AKin-lvyifang/vibeboss`，唯一真源）。
  - 打包 `scripts/build-desktop-artifact.ts` 的 `resolveGitHubPublishConfig`：没设 `T3CODE_DESKTOP_UPDATE_REPOSITORY` / `GITHUB_REPOSITORY` 时默认用我们的仓库。以前本机打的 mac 包没有更新源，等于关着；云端打的 Windows 包因为 GitHub 自带 `GITHUB_REPOSITORY`，0.1.13 起其实已经指向我们仓库。
  - 「更新说明」链接（`apps/web/src/components/desktopUpdate.logic.ts`）和启动失败页的「去下载」链接（`apps/desktop/src/app/DesktopStartupRecovery.ts`）从 T3 仓库改成我们的。
  - 本地模拟更新（`--mock-updates`）优先于 GitHub 源，方便自测。
- **临时签名（ad hoc）的 mac 包不带更新源**：mac 只接受「和当前版本同一签名身份」的更新，临时签名每次打包都不一样，带了也装不上。所以没有本机证书时打包会提示「自动更新已关闭」，包照常能用。
- **一键更新**：侧边栏更新按钮（`SidebarUpdatePill.tsx`）和设置页「版本」按钮（`SettingsPanels.tsx`）：有新版时点一下 → 弹一次确认（T3 原有文案：会中断进行中的任务）→ 后台下载 → 下载完自动安装并重启。原来要点两次（先下载、再点重启）。设置页按钮文字从「下载」改为「安装」。
- **Windows 打包**：`.github/workflows/vibeboss-windows.yml` 附件里多带 `latest.yml` 和 `.exe.blockmap`（更新清单和分块校验文件，发 Release 时要一起传）。

## 三个风险的结论

1. **mac 签名**
   - 已发的 0.1.11–0.1.13 都是临时签名、也没带更新源：**这几版装着的人收不到自动更新，要手动装一次带更新功能的新版**，之后才能自动更新。
   - 从第一个用「VibeBoss Local Signing」证书签的版本起，后续版本只要**还用同一张证书签**，mac 就认作同一身份，自动更新能装上（mac 比对的是证书指纹，不要求苹果认证，自签证书可以）。这一点是按 Squirrel.Mac（mac 端负责替换 App 的组件）的校验规则判断的，尚未用两个真包实测；第一次发两个连续版本时要实测一次。
   - **证书丢了不会让大家永远没法更新**，但会断一次：换新证书后，已装的人自动更新会报错，需要手动下载新版装一次，之后又能自动更新。
   - 所以要**备份证书**（导出 `.p12`，带私钥）。证书只在打包这台电脑的登录钥匙串里，有效期到 2036-11-22。换电脑打包时必须先导入这张证书，否则打出的是临时签名包（不带更新源）。
   - 导出步骤（要方哥同意后在自己电脑上操作，会要求设置导出密码，密码别写进仓库）：
     1. 打开「钥匙串访问」→ 左侧「登录」→ 「我的证书」。
     2. 右键「VibeBoss Local Signing」→「导出…」→ 格式选「个人信息交换 (.p12)」→ 存到网盘或密码管理器等私有位置。
     3. 新电脑上双击 `.p12` 导入登录钥匙串，再在证书「显示简介 → 信任 → 代码签名」设为「始终信任」。
2. **仓库公开**：`AKin-lvyifang/vibeboss` 已是公开仓库，Release 谁都能下载，不需要额外方案。
3. **Windows**：能用。0.1.13 的 Windows 包已经带了指向我们仓库的更新源，只是 Release 里没传 `latest.yml`，所以暂时发现不了新版。以后发版把 `latest.yml` 一起传，已装 0.1.13 的 Windows 用户就能自动更新。Windows 包没签名，更新时不校验发布者，没有签名身份问题。

## 发新版的步骤（让已安装的人收到更新）

以下 push、打 tag、发 Release 都是对外动作，每次要方哥点头。

1. **改版本号**：`apps/desktop/package.json`、`apps/server/package.json`、`apps/web/package.json`、`packages/contracts/package.json` 和 `README.md` 里的版本号一起改（如 0.1.14，参照提交 `chore(release): 0.1.13`）。版本号必须比上一版大，否则已装的人不会认为有新版。
2. **打 mac 包**（在有证书的电脑上）：
   `VIBEBOSS_SKIP_APPLE_SPEECH=1 PATH=$PWD/node_modules/.bin:$PATH node scripts/build-desktop-artifact.ts --platform mac --target dmg --arch arm64`
   - 打包日志里**不能出现**「Ad hoc signed mac build: automatic updates are off」。出现说明证书没找到，这个包不能发。
   - 产物在 `release/`：`VibeBoss-<版本>-arm64.dmg`、`.zip`、`.zip.blockmap`、`latest-mac.yml`。
3. **打 Windows 包**：push 代码后 `gh workflow run vibeboss-windows.yml --ref vibeboss/m1-slim`，下载附件，得到 `.exe`、`.exe.blockmap`、`latest.yml`。
4. **发 Release**：打 tag `v<版本>`，Release 标记为 Latest（正式版，不勾 Pre-release），附件传齐：
   - mac：`.dmg`（新用户手动装）、`.zip` + `.zip.blockmap` + `latest-mac.yml`（自动更新用）
   - Windows：`.exe` + `.exe.blockmap` + `latest.yml`
   - 例：`gh release create v0.1.14 -R AKin-lvyifang/vibeboss --title "VibeBoss 0.1.14" --notes-file <说明> release/VibeBoss-0.1.14-arm64.dmg release/VibeBoss-0.1.14-arm64.zip release/VibeBoss-0.1.14-arm64.zip.blockmap release/latest-mac.yml <Windows 三个文件>`
   - 注意 mac 和 Windows 的 `latest*.yml` 文件名不同，不会互相覆盖；漏传任何一个，对应系统就发现不了新版。
5. **验证**：装着上一版的电脑，点侧边栏更新按钮「检查更新」，应出现新版；点一下走完下载→重启，「设置 → 版本」显示新版本号。
6. **第一次发带更新功能的版本（0.1.14）时**：Release 说明里提醒老用户「这一版需要手动下载安装一次，之后会自动更新」。
