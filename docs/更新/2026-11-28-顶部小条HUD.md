# 顶部小条 HUD（仅 Mac）

- 需求：同时开着几个会话、自己切去别的应用时，不切回 VibeBoss 就能知道谁在等我、谁在干活、谁做完了，并能就地批准或回答。屏幕顶部正中（刘海下面）放一条黑色小条。定稿 Demo 在方哥电脑 `~/Desktop/Personal/Fdesign设计稿/vibeboss-HUD/final/index.html`。
- 行为：
  - 收起时按紧急程度只说一件事：等你批准或回答 > 出错 > 额度剩 10% 以内 > 几个在干活；没事时缩回刘海不显示。
  - 鼠标移上去展开，分“会话 / 额度”两页。会话页分等你、出错了、在干活（带任务清单进度和帮手）、做完了；额度页列出每个已登录账号各周期还剩多少、何时重置。
  - 可以直接批准、拒绝，或回答三项以内的单选提问；点任意一行回到主窗口并打开那个会话。
  - 有会话做完时往下探出一行，6 秒后收回。
  - 正在看的那个会话不上条提醒。
  - 展开和收起是一套弹簧动作（展开略带回弹，收起不回弹），中途改方向会接着当前速度走。静止时不重绘。参数参考了开源的 boring.notch。
  - 设置在“外观 > 顶部小条”：开关、勿扰（只留头像）、头像（跟随“形象”里的图，可在图上选一块、方形或圆形）。设置存在本机浏览器存储里，和形象设置一样。
- 做法：
  - 小条是一个独立的小窗口，自己不连服务端。主窗口已经有全部会话和额度数据，由它算出一份“画什么”的快照发给小条，小条把点击的动作发回主窗口执行。这样不用再开一套连接和登录。
  - 桌面外壳：`apps/desktop/src/vibeboss/VibeBossHud.ts`（创建窗口、置顶到菜单栏之上、摆在主屏顶部正中、平时鼠标穿透）、`hudHtml.ts`（样式）、`hudIcons.ts`（图标）、`apps/desktop/src/vibeboss-hud-preload.ts`（在小窗口里画界面）。
  - 主窗口：`apps/web/src/vibebossHud.ts`（订阅数据、发快照、执行动作）、`vibebossHud.logic.ts`（把会话状态汇总成快照，带单元测试）、`components/settings/VibeBossHudSection.tsx`（设置区）、`vibebossAppearance.ts`（设置项）、`public/vibeboss-hud-figure.webp`（去掉白色描边的默认形象图）。
  - 数据格式：`packages/contracts/src/vibebossHud.ts`。
- 复用 T3：会话状态判断用侧栏同一套函数；批准和回答走现有命令；额度用用量页同一套汇总和“何时重置”文案；窗口写法照权限引导小窗和画中画预览。
- 已知限制：
  - Electron 拿不到刘海的真实宽度，按内置屏幕菜单栏高度判断有没有刘海，宽度固定按 184 点算。
  - 主窗口关闭后没有数据来源，小条随之关闭。
  - 出错的会话只能点进去处理，小条上没有重试。
- 上游注意：
  - 上游文件只加了入口：`apps/desktop/src/ipc/DesktopIpcHandlers.ts`（`installVibeBossHud`）、`ipc/channels.ts`（3 个通道）、`preload.ts`（2 个桥接方法）、`vite.config.ts`（一个打包入口）、`packages/contracts/src/ipc.ts`（`DesktopBridge` 多 2 个可选方法）、`packages/contracts/src/index.ts`、`apps/web/src/appInit.tsx`（`startVibeBossHud`）、`settingsSearch.ts`（3 条搜索登记）。合并冲突时保留这些入口。
  - 快照里的会话状态依赖 `resolveSidebarRowStatus`、`hasUnseenCompletion`、`environmentThreadDetails.pendingRequestsAtom`、`quietThreadAtom`、`collectLimitAccounts`；上游改这些的签名时跟着改 `vibebossHud.ts`。
  - 跑完 `vp run i18n:generate` 仍要再跑 `vp run vibeboss:rebrand`。
