# 个人记忆

- 需求：用户的习惯原来分散在各家智能体自己的全局规则和自带记忆里，互相看不到，很多人也从没写过。现在规则页的「公共规则」改名「个人记忆」，内容照旧写进每一家规则文件的最前面；主控可以直接写，后台每天整理，第一次可以从历史对话生成。记忆交给智能体管：不弹确认、不做撤销，用户看到不对就说或者手改。设计定稿：`~/Desktop/Personal/Fdesign设计稿/vibeboss-个人记忆/index.html`。
- 做法：
  - 数据仍是配置里的 `sharedRules`（字段不改名，不用迁移）。新增 `memoryApi`（整理用的 API 模型：设置里「文本生成器」的一个 + 模型）和 `memoryAutoTidy`（每天整理，默认关）。
  - 主控用 `personal_memory_update` 工具写：`remove` 填原句、`add` 填新句、`section` 指定二级标题（没有就新建）。服务端核对原句存在、超过 16000 字拒绝，写完自动同步所有规则文件（照旧先备份）。被派活的成员调用会被拒绝。
  - 主控规则文件末尾多一节英文的「Personal memory」说明：什么时候写、写什么、不写什么。没有改每轮提示（改了会让 Claude 回放测试对不上，也多一处上游冲突点）。
  - 生成和整理是同一套：读这台机器上所有对话里用户自己发的消息（去掉 `<system-reminder>` 这类注入块，跳过 6000 字以上的粘贴），按对话分批（每批约 3 万字）让模型提取候选习惯和出现次数，再合并成一份 Markdown。生成还会读各家已有的专属规则和 Claude、Codex 自带的记忆文件；整理只读上次之后的新消息。
  - 合并结果要过检查：必须有条目、不超长、不能比原来短太多、上次整理后用户手写的句子意思必须保留（相似度 0.6），不过就整份不写，原因显示在页面上。
  - 生成和整理只用 API 模型（11-29 改）：各家命令行启动时会读自己的全局规则文件，模型会把那些规则当成用户习惯，换 API 就没有这层干扰。没选 API 时点「生成」「整理」只弹出选择；一个 API 都没有时给「去设置里添加 API」。选了 API 自动带上它的第一个模型。API 收到的提示末尾要求回 `{"transcription": …}`，因为文本生成器不像命令行能强制格式。
- 每天整理：默认关，选了 API 才能打开。打开后后台每 30 分钟查一次，满 24 小时、且有 3 个以上新对话才跑。同一时间只跑一个。
  - 改动记录：谁（主控、你、整理、从历史对话生成）、来自哪个会话或用了哪个模型读了几个对话、加了哪几行删了哪几行，存在数据目录 `vibeboss/personal-memory.jsonl`（保留 500 条），只看不撤销。上次整理时间和读到哪条消息存在 `personal-memory.meta.json`。
  - 规则页：个人记忆排第一、默认打开。空的时候只有「从历史对话生成」「自己写」。有内容时顶部一行：字数 / 6000、上次整理时间或进度、「记录」（右侧抽屉）、「整理」和旁边的箭头（选 API 和模型，开关每天整理）。
  - 别的标签有未保存的草稿时，保存不会把旧的个人记忆写回去盖掉主控或整理刚写的内容（只有在这里改过个人记忆才带上草稿里的版本）。
  - 对话里「已更新个人记忆」旁边有「查看」，跳到规则页的个人记忆。
  - 规则检查里的“公共规则”字样同步改成“个人记忆”。
- 复用 T3：RPC 和权限、MCP 工具通道（`McpToolAccess.actsAsCaller`、会话专用工具标注）、小模型调用（`generateTranscriptionPostProcessing`，交给 T3 的文本生成器）、`useTextGenerationTargets` 和 `ProviderSelect`/`ModelSelect`、`Sheet`、`Switch`、后台任务 `forkParked`。

- 实测（开发实例，干净数据库 + 合成对话，Claude Haiku）：手写一条并同步；三条合成对话跑「整理」，结果只含对话里出现的习惯，手写那条保留；让 Haiku 主控调用工具写入「称呼」分区，三家预览规则文件都同步更新；对话里「查看」跳到规则页个人记忆；「记录」抽屉显示每次增删的行。没在真实历史上跑「从历史对话生成」（会把真实对话发给模型，需要方哥自己点）。
- 踩到的坑（已改为只用 API 解决）：整理调用各家命令行时，命令行会自动加载它自己的全局规则文件，模型会把那些规则当成“观察到的习惯”（第一次实测混进了合成对话里没有的内容，还写反了一条）。提取和合并提示里加了“只用本次给的内容、忽略别处加载的规则”后基本干净，仍可能有零星措辞残留。后来改成只用 API 模型，这个问题不再存在。实测用本地假 API（127.0.0.1）跑通：选 API → 整理 → 记录里显示「整理 · mock-small」。
