# 删除遥测上报（任何数据都不发往 T3 或第三方服务器）

- 需求：网上指出 T3 Code 默认开启 PostHog 遥测、曾读取本地账号文件上报、可把日志和追踪导出到外部服务。方哥要求在 VibeBoss 里查清并删除，绝不能上传到服务器。
- 核对结论：
  - PostHog 遥测（发往 `ingest.t3.codes`）：VibeBoss 原已默认关闭，但设环境变量仍能打开 → 本次删除发送代码。
  - 读 `~/.claude.json`、`~/.codex/auth.json` 拿账号 ID：上游已移除，VibeBoss 代码里没有，身份只用本机随机 ID。
  - OTLP 导出（日志、追踪、指标发到自定义地址，资源监控的进程数据也走这条）：默认没有地址，但可在设置或环境变量里填 → 本次删除导出入口。
  - 中继追踪（用 T3 Connect 时发往追踪服务）：上游默认开 → 本次删除。
  - 删除的会话仍留在本地数据库、资源监控读取本机进程：只在本机，不上传，本次不改。
- 做法：
  - `apps/server/src/telemetry/AnalyticsService.ts`：删掉 PostHog 发送实现、内置密钥和上报地址，只留服务接口和空实现（所有调用什么都不做）。删除 `AnalyticsService.test.ts`。
  - `apps/server/src/cli/config.ts`：服务端 OTLP 地址固定为空。
  - `apps/desktop/src/app/DesktopObservability.ts`：桌面端 OTLP 视为关闭。
  - `packages/shared/src/otelEnvironment.ts`：`isRelayTracingEnabled` 恒为 false；删掉不再使用的 `isDoNotTrackSet`。
  - 测试：删掉只验证导出功能的用例（`config.test.ts` 6 条、`DesktopObservability.test.ts` 2 条），中继追踪测试改为「始终关闭」。
- 复用 T3：保留 `AnalyticsService` 服务标签，调用方不用改；网页端追踪只发到本机服务端，不受影响。
- 仍会联网的：模型调用（直接发给 Claude、Codex 等模型商）、检查更新（访问我们自己的 GitHub Releases）、用户主动开启的 T3 Connect 远程连接。
- 上游注意：合并上游时这几个文件容易冲突，一律保留 VibeBoss 的空实现和置空；上游新增的遥测或导出入口要同样切断，合并后搜 `posthog`、`OtlpTracer.make`、`OtlpLogger.make`、`OtlpMetrics.layer`、`ingest.` 复查。
