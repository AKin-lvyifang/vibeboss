# 钥匙串改用系统 security 工具读取（不再弹窗）

- 需求：装了固定签名的 0.1.14 后，「VibeBoss 想要访问钥匙串中的密钥 gemini」仍持续弹窗。
- 原因：这个条目是 Antigravity 命令行（go-keyring）经 `/usr/bin/security` 写入的登录凭证，VibeBoss 读它来显示 Antigravity 额度。条目的「分区」授权要认苹果团队 ID；自签名证书没有团队 ID，系统只能记这一版程序的指纹（cdhash），每次打包都变，所以固定签名只解决了一半。
- 做法：macOS 上改为调用 `/usr/bin/security find-generic-password -w` 读取。`security` 本来就是条目的创建者，在授权名单和 `apple-tool:` 分区里，读取不弹窗，不受 VibeBoss 更新和 Antigravity 重新登录影响。Windows、Linux 不变。
- 复用 T3：Effect `ChildProcessSpawner` 调系统命令（同 `ChromiumKeys.readLinuxSecret`），解码沿用 `decodeGoKeyringSecret`。
- 改动文件：
  - 新增 `apps/server/src/provider/vibebossMacKeychain.ts`。
  - `apps/server/src/provider/antigravityUsageLimits.ts`：`makeAntigravityUsageProbe` 里 macOS 走新读取。
  - `apps/server/src/provider/Drivers/AntigravityDriver.ts`：给额度探针提供 `ChildProcessSpawner`。
- 验证：用新代码读真实条目成功、解码正确、无弹窗；不存在的条目返回空。`vp run check:changed` 全过。
- 上游注意：合并上游时若 `makeAntigravityUsageProbe` 的 `readKeyringSecret` 默认值被改，保留 macOS 分支；驱动里的 `ChildProcessSpawner` 提供也要保留。
