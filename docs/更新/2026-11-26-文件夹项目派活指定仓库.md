# 文件夹项目派活：指定改哪个仓库

- 需求：echoink-remote 这类项目，根目录是普通文件夹，里面放着几个 git 仓库。主控派多个子任务并行写代码时，要给每个子任务一份独立副本（worktree），而且副本要带上主控刚提交的内容。
- 上游已有：T3 `62d6abfd` 让文件夹项目也能开副本，做法是给每个仓库都开一份，从各自的默认主线开始。这样子任务看不到主控在功能分支上刚提交的方案。
- 我们加的：`delegate_task` 多一个可选参数 `repository`（仓库名或路径）。传了就只给这个仓库开副本，从它当前所在的分支开始；不传就照上游的做法。
- 复用 T3：任务文件夹（`TaskFolders`）和 worktree 策略里现成的 `repositories` 字段，没新造机制。
- 改动文件：`apps/server/src/mcp/vibebossFolderWorktree.ts`（新，按名字或路径找仓库）、`OrchestratorMcpService.ts`（`folderRepositoryStrategy` 和一处入口）、`packages/contracts/src/orchestratorMcp.ts`（新参数）、两份测试、`agentContextBudget.json`（工具说明变长，体积基线同步）。
- 没做：T3 要求改了给模型看的工具说明就跑评测（`evals/mcp-tool-use`，会花钱调用模型），这次没跑。
- 上游注意：上游再改 `delegate_task` 的文件夹分支（`isNonGitProject` 那段）时，保留 `input.repository` 的判断；上游若自己加了类似参数，以上游为准撤掉这处。
